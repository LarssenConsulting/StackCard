# Discover v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `discover-agent`, a Python agent for Ubuntu 24.04 that collects an inventory and sends it over HTTPS, and the central Laravel + Filament application that receives it, links sites to databases, and displays the result.

**Architecture:** The agent is a Python package that uses only the standard library and is made of independent collectors. They produce a versioned JSON snapshot, which the agent POSTs to the central API with a per-server Sanctum Bearer token. The central stores the raw snapshot, replaces the current state of that server in normalized tables, then recomputes the site→database links for the whole fleet.

**Tech Stack:** Python ≥ 3.12 (stdlib, `unittest`), systemd, dpkg; PHP 8.3+, Laravel (latest stable), Filament (latest stable), Sanctum, Pest, MySQL (prod) / SQLite (tests); Docker `ubuntu:24.04` for packaging and integration testing.

**Spec:** `docs/superpowers/specs/2026-10-14-discover-design.md`

**Execution mode:** native (the user explicitly asked to start immediately without intermediate review).

## Global Constraints

- Target OS for the agent: Ubuntu 24.04. Runtime: `python3 (>= 3.12)`, stdlib only.
- The agent never transmits passwords, hashes or keys. Config keys containing `PASS`, `SECRET`, `KEY`, `TOKEN` or `SALT` are ignored when read.
- HTTPS is mandatory and certificate verification cannot be disabled; `ca_file` and `pin_sha256` are optional.
- Agent files: `/etc/discover-agent/agent.conf` and `/etc/discover-agent/credentials` (0600), `/var/lib/discover-agent/state.json`.
- Timeout of 15 s per subprocess. Collector errors go into `errors[]` and never prevent the send.
- `schema_version: 1`; dates are ISO 8601 UTC with the `Z` suffix.
- API: `POST /api/v1/enroll`, `POST /api/v1/inventory`; 5 MB maximum; 30 req/min per token.
- Enrollment token: single-use, 24 h, stored as SHA-256.
- Snapshot retention: 30 days. A server is stale when it has sent nothing for 3 h. Certificates are flagged when they expire in less than 30 days.

## Review Focus

1. **Same domain on :80 and :443** (redirect vhost plus HTTPS vhost): both vhosts are reported as separate sites, distinguished by port, and the central does not treat them as duplicates. → tests in Task 3 and Task 11.
2. **Real-world `.env` files**: quoted values, `export ` prefix, comments, spaces around `=`, empty `DATABASE_URL` → parsed without crashing, and passwords never appear in the output. → Task 5.
3. **Node site whose process is not running** (port not listening): `type=node`, `system_user=null`, no exception. → Task 4.
4. **MySQL inaccessible** (root with a password, service stopped): `mysql=null`, an entry in `errors[]`, and the snapshot is still produced. → Task 6.
5. **Re-sent snapshot with one site removed**: the site disappears from the current state, history is preserved, and links are recomputed. A revoked token returns 401. → Task 11.
