# Agent 0.5 : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** collecter 14 sections d'état du serveur en lecture seule, les stocker avec historique sur le central et les afficher dans un onglet Filament.

**Architecture :** `discover_agent/sections/` contient un module par section et un exécuteur qui produit l'enveloppe (`collected_at`, `sha256`, `error`, `source_errors`, `data`). Le central stocke chaque section dans `server_sections`, en n'ajoutant une ligne que si elle a changé. Le format existant du snapshot ne change pas.

**Tech Stack :** Python ≥ 3.10 (bibliothèque standard uniquement, `unittest`) ; Laravel 13, Filament 5, Pest.

**Spec :** `docs/superpowers/specs/2026-10-31-agent-0.5-design.md`, et `_inputs/stackcard-agent-0.5-spec.md` pour les commandes et champs qu'elle ne modifie pas. Lire les deux.

## Contraintes globales

- **Ne jamais commiter ni pousser** : l'utilisateur le demande explicitement, à la fin. `_inputs/` n'est jamais commité.
- Agent : bibliothèque standard uniquement, aucune installation, lecture seule, aucune instruction reçue du central. La réponse reste `{"status": "ok"}`.
- Tout appel système passe par `util.run`, avec `runner`/`reader` injectables. Les tests n'utilisent que des fakes.
- `schema_version` reste à 1 ; `sections` est optionnelle sur le central.
- Délais : 30 s (niveaux 1 et 2), 300 s (niveau 3). Plafonds : 4 Mio par section, 16 Mio par envoi.
- Interface et messages en français. Identifiants et commentaires de code en anglais, comme le code existant.
- Les fichiers `central/app/Filament/Resources/Servers/RelationManagers/DatabasesRelationManager.php` et `central/tests/Feature/Filament/AdminPanelTest.php` portent des modifications non commitées d'avant ce travail : ne pas les toucher.

## Points d'attention en revue

Chacun a son test dans la tâche indiquée.

1. Sortie `ss` atypique (`[::]:80`, `*:80`, `127.0.0.1%lo:53`, socket sans processus) : parsée sans erreur, `public` correct. Tâche 4.
2. Secret sous une forme courante dans un cron (`PGPASSWORD=x pg_dump`, `MAILTO=`, `mysql -pX`, `https://u:p@h`) : masqué, sans abîmer une ligne `MAILTO=admin@ex.com`. Tâche 1.
3. Ligne apt avec options et identifiants (`deb [signed-by=/k arch=amd64] https://u:p@h/ubuntu noble main`, `.sources` multi-blocs, `Enabled: no`) : URI masquée, aucun `Signed-By`. Tâche 3.
4. Webroot hostile (FIFO, boucle de liens, binaire non UTF-8, très longue ligne, DocumentRoot manquant) : l'analyse se termine, le fichier ignoré est compté dans `skipped_files`. Tâche 9.
5. Envois répétés et absences (agent 0.4 sans `sections`, même `sha256`, `skipped_not_due` après une collecte réussie) : aucune donnée perdue ni ligne inutile. Tâche 11.
